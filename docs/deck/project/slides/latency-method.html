The latency programme

Every number in this deck comes from one repeatable measurement on a fresh AWS stack

One scripted run

Provision, deploy, 20,000 warm-up then 100,000 timed orders at 1,000 per second, record, destroy. Both engines journaling.

Honest timing

Clocked from the intended send, so a late sender cannot hide queueing. The sender's slip is recorded beside it.

A network baseline

sockperf measures the raw kernel TCP round trip between the same hosts in the same run.

Host checks

Each loop thread is sampled during the run: on its core, spinning, isolated, no interrupts, preemptions counted. A failed check fails the run.

Stage timestamps

An optional mode stamps every engine stage on both sides. It costs about 1.5 µs, so headline runs leave it off.

A permanent record

Every run appends one line to a history file in the repository: commit, host, options, percentiles. 56 runs to date.

One way leads

Headline figures are one way, marked ≈: half the measured round trip. What is measured is the round trip, an order out of the initiator to its acknowledgement back, timed on one clock, so no clock synchronisation is involved; it sits in grey or in brackets beside each one-way figure.

One command runs the whole cycle; the same script measured every milestone in this deck; change one thing, judge it on one stack

Before the numbers, the method. Everything was measured the same way on throwaway AWS stacks with the host state verified during the run, the sender's own lateness corrected for, and a raw network baseline alongside. Two stacks of the same type can differ by several microseconds, so the firmest evidence is always an A/B on one stack minutes apart. That discipline is what lets us say which change did what.
