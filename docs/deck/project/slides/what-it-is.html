One engine between your applications and the exchanges, built so it is never the slow part

Connectivity

Initiator and acceptor sessions for FIX, OUCH and three binary exchange protocols; logon, heartbeats, sequence recovery and resend handled by the engine. The next protocol is a module.

Latency by design

A single busy-spinning thread per event loop, flyweight messages over direct buffers, lock-free ring buffers, and zero bytes allocated per message, enforced by tests.

Durable sessions

Every message journaled before it is sent, on Chronicle Queue, a memory-mapped log, and optionally copied over Aeron, a UDP messaging library, to another host. Resend and restart recover from the log.

Operable

Admin REST and WebSocket API, Prometheus metrics with Grafana dashboards and alerts, and OmniView, a web console for session health and control across every engine.

Java 25

Plain JVM, no custom runtime. HOCON configuration, components with a managed lifecycle and active/standby states, a multi-protocol exchange simulator, and a kernel-bypass transport (the network card driven from the engine's own thread, no operating system in the data path) as a switch.

Maven multi-module project; engines, persistence, admin, metrics and tooling are separate modules

Omni-Bridge is an exchange connectivity engine. It handles the session layer of the venue protocols so applications only deal with orders and executions. It is written to be fast by construction rather than tuned afterwards, it journals everything, and it ships with the monitoring and console that operations teams need.
