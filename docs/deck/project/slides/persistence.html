Persistence: every message on disk before it is sent, under a microsecond per write

What is stored

One Chronicle Queue stream per session: an append-only memory-mapped file, daily rolling, found again at startup. Each entry: timestamp, direction, sequence number, raw bytes.

What it is for

ResendRequests are answered from the journal with PossDup set. On restart, sequence numbers come back from the latest entries. Replay by sequence or by time.

Tooling on the journal

A log viewer, a validator that compares local and remote copies entry by entry, and an MCP server so an assistant can query messages and session status.

Cost on the hot path

0.4 to 0.8

µs per journal write at p50

0 B

allocated per message, store on

The page-fault finding

The first write to each 4 KB page of the mapped file cost a 1 to 3 µs fault on the loop. A helper thread now faults 1 MB ahead: the write's p99.9 fell from 34 to 42 µs to 3 to 5, the round trip's max from 1,030 µs to 316.

Store type per session: Chronicle, plain memory-mapped, Aeron replication, or none.

Modules persistence and persistence-aeron; the pretouch thread is persistence.pretouch-ahead, default 1 MB

The journal is the part a risk officer cares about. Nothing leaves the engine before it is on disk, and the session can be rebuilt from the log. The engineering effort went into making that write cost less than a microsecond and allocate nothing. The page-fault story is a good example of the method: a stage timestamp showed a tail on the write, the cause was in how the file was mapped, and a background thread removed it without touching the format. Inbound messages are logged on receive, outbound at drain with the sequence number read from the ring. Logging and tracing are separate per-session switches.
